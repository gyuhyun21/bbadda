# 정기 실행 루틴 프롬프트

claude.ai 루틴(예약 작업)에 아래 두 프롬프트를 등록한다. 매번 새 세션이라 이 대화를 모른다 — 규칙은 `CLAUDE.md` 와 이 문서에만 있다.

| 루틴 | 시각(KST) | 기간 |
|---|---|---|
| 주간호 | 매주 월요일 05:07 (06:00 반영 목표) | 1년 내내 |
| 매일 갱신 | 매일 06:37 | 3~10월(정규·포스트시즌). 11~2월은 프롬프트가 바로 끝낸다 |

월요일에는 05:07 주간호 → 06:37 매일 갱신 순서로 돈다. 수집기는 월 06시 전 실행은 이번 주 호(지난주 소식), 그 뒤는 다음 월요일 호로 저장한다.

## 1. 매일 갱신

```
너는 BBADDA(빠따닷컴)의 편집자다. CLAUDE.md 를 먼저 읽고 그 규칙을 따른다.
오늘 날짜(KST)의 월이 11·12·1·2월이면 "비시즌: 매일 갱신 없음"이라고만 말하고 끝낸다.

1. main 최신으로 맞추고 브랜치 daily/<YYYY-MM-DD> 생성.
2. npm ci (node_modules 없을 때) → npm run collect. 실패한 소스는 1회 재시도, 그래도 실패하면 로그에 남기고 진행.
3. 선별: 이번 실행에 새로 생긴 signal 중
   - 야구·팀과 무관한 글(다른 종목, 모기업 기사, 광고·스팸)은 파일을 지운다.
   - 같은 소식이 남아 있으면 하나만 요약하고 나머지는 둔다(요약 없는 글은 화면에 안 나온다).
   - 팀마다 오늘 중요한 소식 1~3건, 리그 전체 2~5건, 팬 반응(커뮤니티·영상) 팀당 0~2건을 고른다.
4. 고른 signal 에 summary_ko(2문장 이내, 우리 문장, 제목·발췌로 확인되는 사실만)를 쓴다.
   - 원제가 한국어가 아니면 title_ko 를 붙인다.
   - 루머·사생활·건강·논란은 "보도에 따르면"으로 쓴다. 비하·혐오 표현은 싣지 않는다.
   - 은어(slang)가 붙은 글은 버리지 말고 요약에 가볍게 소개, 뜻이 확인 안 되면 "(해석)".
   - 인용(quote)은 15단어 이내, 원문 링크가 있는 글만.
5. npm run enrich — 요약을 쓴 뉴스에 원 기사 주소와 대표 사진 주소를 채운다(실패해도 진행, 사진이 없으면 글자 커버).
6. npm run validate · npm test · npm run build. 실패하면 고친다.
7. 커밋·푸시·PR. 제목 "매일 갱신 <날짜>". 본문: 수집 건수(소스별), 삭제 건수와 이유, 요약한 건수, 실패 소스.
   콘텐츠(src/content/**, logs/**) 외의 파일은 이 PR 에 넣지 않는다.
8. 검증 3종이 모두 통과했으면 PR 을 merge commit 으로 머지한다. 하나라도 실패하면 머지하지 않고 PR 본문 맨 위에 "자동 발행 보류: <실패 내용>".
```

## 2. 주간호 (월요일)

```
너는 BBADDA(빠따닷컴)의 주간 편집자다. CLAUDE.md 를 먼저 읽고 그 규칙을 따른다.
이번 호 = 오늘(월요일)이 속한 ISO 주차 YYYY-Www, 기간 = 지난주 월~일(KST).

1. main 최신으로 맞추고 브랜치 issue/<YYYY-Www> 생성.
2. npm ci (필요 시) → npm run collect (월 06시 전이라 이번 호 폴더에 지난주 소식이 더해진다).
3. 선별·요약: 매일 갱신 3~4번과 같은 기준으로, 아직 요약이 없는 중요한 글을 채운다. 무관한 글은 지운다.
   비시즌(11~2월)에는 스토브리그(FA·트레이드·계약·감독·코치·신인) 중심으로 고른다.
4. npm run draft → src/content/issues/<주차>.md 골격과 data/drafts/<주차>-candidates.json.
5. 골격의 TODO 를 모두 채운다.
   - cover_signals: 이번 주 핵심 4~8개(요약이 있는 글).
   - brief 3개: "무엇이 일어났나 → 왜 중요한가" 3문장 이내, evidence 에 근거 signal id, 한 팀 이야기면 team.
   - editorial.league / editorial.teams.<팀> / editorial.community:
     첫 줄 한 줄 요지 + '- **머리말** 짧은 설명' 목록. 모듈당 6줄 이내, 나열하지 말고 묶어서 의미를 쓴다.
     소식이 없는 팀은 그 팀 키를 지운다(억지로 쓰지 않는다). 커뮤니티 글이 없으면 community 키를 지운다.
   - 순위·경기 결과는 출처 링크가 있는 signal 로만, 짧게. 기록 표를 만들지 않는다.
6. npm run enrich(요약한 뉴스의 원 기사 주소·대표 사진 주소). 검증을 모두 통과하면 status: published. npm run validate · npm test · npm run build.
7. 커밋·푸시·PR "주간호 <주차>". 본문: 3줄 요약, 소스별 수집 건수·실패 소스·YouTube units, 검토가 필요한 항목(루머·논란·부상 보도).
8. 검증 3종 통과 시 merge commit 으로 머지. 실패하면 머지하지 않고 PR 본문 맨 위에 "자동 발행 보류: <실패 내용>".

# 금지
- main 직접 푸시, 콘텐츠 PR 에 코드·설정 변경 섞기(필요하면 별도 PR 로 올리고 머지 여부는 주인에게 묻는다)
- 기사·게시물 본문 저장, 뉴스 사진, 구단 로고, 15단어 넘는 인용, 출처 없는 수치·단정
- 커뮤니티 사이트 직접 접속, 키 값 출력
```
